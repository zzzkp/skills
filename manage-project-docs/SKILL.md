# 项目文档管理

## 目标

按“文档总索引 → 工作空间总览 → 分类索引 → 项目总览 → 技术模块总览 → 专题文档”组织知识，渐进读取必要内容，避免重复文档和巨大 README。环境信息和研发辅助资料按所属分类进入专题，不强制补齐项目或技术模块层级。

## 定位文档范围

1. 开始目录枚举或内容检索前，读取适用的 `AGENTS.md`，并排除 `.secrets/` 和已知的历史本地密钥配置。不得通过扩大搜索范围绕过访问约束。
2. 优先使用用户明确指定的文档目录、工作空间、分类和项目名。已明确项目或专题路径时直接使用该范围，结合上级索引确认归属。
3. 需要定位文档根目录时，可读取用户指定的文档路径环境变量；没有指定时检查 `PROJECT_DOCS_ROOT` 并确认目录存在。不要求已明确路径的任务另设环境变量，也不枚举密钥环境变量。
4. 按文档根 `README.md`、工作空间 `README.md`、分类 `README.md` 逐级定位相关项目或专题。工作空间是资料归属范围，可以包含多个代码项目，不等同于代码仓库根目录。
5. 工作空间或项目存在多个候选、无法可靠匹配时，列出少量候选并向用户确认。
6. 查阅或修改任务找不到目标目录时，不自行创建；生成新工作空间、项目或专题文档时按用户要求创建。

## 目录模型

```text
<docs-root>/
├── README.md                         # 工作空间总索引
├── AGENTS.md                         # AI 访问约束
├── 密钥管理.md                       # 通用密钥管理说明
├── .secrets/                         # 本地忽略，按工作空间分组
│   └── <workspace>/
│       └── DB_PASSWORD              # 文件名是键名，内容是明文值
└── <workspace>/
    ├── README.md                     # 工作空间入口和分类索引
    ├── 环境信息说明/
    │   ├── README.md
    │   └── <环境专题>.md
    ├── 业务模块代码/
    │   ├── README.md
    │   └── <项目或业务模块>/
    │       ├── README.md             # 项目概览、代码路径和技术模块索引
    │       ├── frontend/README.md
    │       ├── backend/README.md
    │       ├── database/README.md
    │       └── operations/README.md
    └── 研发辅助/
        ├── README.md
        └── <跨模块工具或专题>/README.md
```

- 文档根 `README.md` 维护工作空间总索引和通用约定；工作空间 `README.md` 维护范围和分类索引；分类 `README.md` 维护项目或专题索引。
- `环境信息说明/` 维护数据库连接、服务器地址、部署入口等环境专题，并引用根目录密钥管理说明。
- `业务模块代码/` 按项目或业务模块维护业务知识、技术实现、SQL、配置、脚本及附件；模块专属资源随所属模块维护。
- `研发辅助/` 维护跨业务模块的研发工具、工作汇总规范及配套脚本。
- 项目根 `README.md` 只保留项目概览、代码路径、一级索引和维护约定。
- 项目内的技术模块 `README.md` 只保留模块概览、关键约定和专题索引。沿用已有 `frontend/`、`backend/`、`database/`、`api/`、`deployment/`、`operations/`、`scripts/` 等划分，按实际内容使用。
- 详细内容放入所属分类、项目或技术模块下单一主题的专题文档。
- 新增前检查已有索引和近似主题，避免 `backend/`、`后端/`、`server/` 等重复结构。

## 密钥存放与访问

- 访问令牌、密码等值统一保存在文档根目录 `.secrets/<工作空间名称>/<键名>`，工作空间目录名与文档中的工作空间名称一致。一个文件保存一个值，使用 UTF-8 明文，不加扩展名。例如 `.secrets/浙江电信/DB_PASSWORD` 的内容就是密码，不写 `DB_PASSWORD=`、引号或 JSON/YAML 包装，也不使用加密或容器文件。
- 人工创建或更新时，直接用文本编辑器修改对应文件。键名在同一工作空间内唯一，不同工作空间可以使用同名键；同一工作空间有多个环境时，使用 `MASTER_DB_PASSWORD` 等明确的键名区分。新增工作空间只需创建同名子目录，无需登记到读取工具。
- `.secrets/` 必须加入 Git 忽略。Markdown、可提交配置模板和命令示例只登记连接入口、键名及用途，不填写实际值；密钥值不复制到文档、报告、日志或聊天记录。
- 涉及密钥操作说明时，先读取文档根目录的 `密钥管理.md`；各项目引用该说明，避免重复维护细则。
- 应用代码在业务运行时按工作空间名称和键名读取 `.secrets/<工作空间名称>/<键名>`。已有公共读取函数时保留极简文件读取逻辑；缺少必填文件或内容为空时提示工作空间、键名和文件位置，不增加其他工作空间、根目录同名文件、环境变量或历史配置的回退读取。
- AI 不直接打开或读取 `.secrets/` 中的文件，也不调用读取函数取值。核对文档和接入方式时只检查键名、说明及调用代码，不以读取实际值验证结果。
- 密钥迁移及读取工具修改仅在用户请求包含这些操作时处理；迁移作为不透明操作，仅报告成功状态和条目数，不查看或展示值。

## 标准工作流

1. 确认文档根目录、工作空间、分类、目标项目或专题及任务类型，遵守上述访问边界。
2. 按需沿相关索引进入目标文档；业务资料先确认项目 `README.md` 的代码路径，再读取相关技术模块索引；环境资料和研发辅助资料从分类索引直接进入对应专题。
3. 需要细节时再读取少量相关专题；涉及密钥约定时读取根目录 `密钥管理.md`，不读取实际值。
4. 优先更新已有文档；只有现有主题无法承载时才新增分类、项目、技术模块或专题。
5. 新增、删除、迁移或重命名文档后，同步更新直接上级索引和所有相关链接；路径变化时同步修正配套脚本、配置及命令示例中的相关路径。
6. 完成后检查归属、主题边界、相对链接、代码路径、密钥约定和修改范围。

## 路径规则

- 项目文档位于 `<docs-root>/<workspace>/<分类>/<项目或业务模块>/`；环境专题位于 `<docs-root>/<workspace>/环境信息说明/`；跨模块工具和工作汇总专题位于所属工作空间的 `研发辅助/`。
- 在项目根 `README.md` 中记录项目代码路径；不同项目分别登记，不把工作空间目录作为统一代码根目录。
- 文档引用代码文件时，以所属项目登记的代码路径为基准写代码仓库内相对路径；文档配套脚本和资源以其实际所属目录为准。
- 文档之间的 Markdown 链接以当前文档位置为基准。
- 不在专题文档中重复写绝对代码路径。
- 删除或重命名文档时修正全部入站链接。

## 创建与修改规则

- 保留项目已有术语、标题层级、命名和链接风格。
- 只修改用户请求相关的工作空间、分类、项目、技术模块和主题。
- 新增工作空间时创建工作空间 `README.md`，登记已有或本次需要的分类，并更新文档总索引。
- 新增分类时创建分类 `README.md` 并更新工作空间索引；新增项目或业务模块时创建项目 `README.md` 并更新分类索引。
- 新增项目内的技术模块时创建模块目录和模块 `README.md`，并更新项目根索引。
- 新增专题时放入所属分类、项目或技术模块，并更新直接上级索引。
- 环境说明记录信息来源、核对日期和适用环境；说明连接信息已登记与实际连通性已验证的区别。
- 一个专题只覆盖一个主要主题；内容跨多个读者或场景时继续拆分。
- 需要新文档骨架时使用 `assets/templates/` 中的模板。

## 完成检查

- 检查工作空间、分类和项目归属是否正确，新增、删除、迁移和重命名是否同步更新索引。
- 检查 Markdown 相对链接能否从当前文件位置解析。
- 检查目录迁移是否同步更新配套脚本、配置和命令示例中的相关路径。
- 检查是否存在重复主题、重复模块或巨大 README。
- 检查代码路径是否以所属项目登记的代码路径为基准。
- 检查文档、模板和命令示例是否仅引用工作空间、密钥键名和统一管理说明，是否统一采用 `.secrets/<工作空间名称>/<键名>` 明文文件；不通过读取密钥值检查存储结果。
- 检查是否修改了用户未要求的工作空间、分类、项目或模块。
- 回答查阅问题时说明信息来自哪个工作空间、项目或专题及哪些文档。
